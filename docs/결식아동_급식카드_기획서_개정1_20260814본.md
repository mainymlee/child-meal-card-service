# 한끼 — 결식아동 급식카드 지원 웹앱 기획서

> 기준 UI: 저장소 루트의 `한끼_웹앱_v10 (1).html`<br>
> 개발 원칙: 기준 HTML은 수정하지 않고 Next.js 앱에서 별도로 구현한다.<br>
> 배포: Vercel / 지도: 카카오맵 JavaScript API<br>
> 최초 작성: 2026-08-11 / 현행화: 2026-08-18

## 1. 프로젝트 개요

**한끼**는 급식카드를 사용하는 아동이 지금 이용할 수 있는 가맹점을 쉽게 찾고, 한 끼 예산 안에서 균형 있는 메뉴를 고르며, 직접 입력한 잔액을 기간 안에 사용할 수 있도록 돕는 모바일 우선 웹앱이다.

### 핵심 가치

- **찾기 쉽게**: 동네·현재 시간·거리·이용 조건에 맞는 가맹점을 지도와 목록으로 제공한다.
- **고르기 쉽게**: 혼밥, 포장, 1만 원 이하 등 실제 이용 조건과 메뉴 균형을 반영한다.
- **놓치지 않게**: 입력한 잔액으로 하루 권장 사용액과 소멸 예상액을 계산한다.
- **낙인 없이**: 보호자 감시나 소비 추적 없이 사용자 본인이 기기에서 관리한다.

### 대상

- 1차 지역: 강원특별자치도 춘천시
- 대표 사용자: 방과 후·주말·방학에 혼자 끼니를 해결하는 급식카드 이용 아동
- 대표 페르소나: 김지민(가상 인물), 11세, 춘천시 후평동 거주

## 2. 문제와 해결 방식

급식카드 가맹 식당이 존재해도 현재 영업 여부, 혼밥 편의성, 포장 가능 여부, 한 끼 한도와 실제 결제 가능 여부를 한 번에 확인하기 어렵다. 이 선택 부담은 익숙하고 접근하기 쉬운 편의점 이용 편중으로 이어질 수 있다. 카드사 연동이 없다면 잔액을 남은 기간에 맞춰 관리하기도 어렵다.

한끼는 **지금 갈 수 있는 곳 → 부담 없이 이용할 수 있는 곳 → 균형 있는 메뉴가 있는 곳** 순서로 탐색을 돕는다. 식당 이용이 어려울 때는 편의점을 배제하지 않고 한 끼 한도 안의 균형 조합을 제안한다. 잔액은 사용자가 직접 입력하며, 계산 결과가 실제 카드 잔액을 보장하지 않는다는 점을 명시한다.

## 3. 제품 범위

### MVP 포함 기능

1. 동네 선택 및 잔액 입력 온보딩
2. 홈 잔액 요약, 하루 권장 사용액, 소멸 예상액
3. 동네별 급식카드 가맹점 지도·목록
4. 업종·영업 여부·혼밥·포장·예산·거리 필터
5. 조건 기반 가맹점 및 메뉴 추천
6. 편의점 균형 조합과 주변 편의점 안내
7. 가맹점 상세, 즐겨찾기, 카카오맵 보기·길찾기
8. 급식카드 결제 불가 제보와 추천 순위 반영
9. 규칙 기반 대화형 도우미
10. 사용자 조건 기반 복지 정보 매칭
11. 동네·조건·알림 설정·즐겨찾기 관리

### MVP 제외 기능

- 카드 발급·신청·결제·충전
- 카드사 실시간 잔액 및 결제 내역 연동
- 복지 신청·접수 대행
- 보호자·교사용 소비 감시
- 정확한 GPS 위치의 서버 저장
- 실제 푸시 알림 발송
- 생성형 AI 또는 외부 LLM 호출
- 실시간 영업정보·메뉴·가격 자동 수집
- 자체 길안내 엔진

## 4. 기준 HTML과 화면 구조

`한끼_웹앱_v10 (1).html`은 UI·상호작용 기준 자료이며 배포 파일로 직접 사용하지 않는다. 실제 서비스는 접근성, 라우팅, 유지보수와 Vercel 배포를 위해 Next.js App Router로 분리한다.

| 화면 | 경로 | 주요 기능 |
|---|---|---|
| 동네 선택 | `/onboarding/dong` | 주 이용 동네 선택 |
| 잔액 입력 | `/onboarding/balance` | 최초 잔액 입력 또는 건너뛰기 |
| 준비 완료 | `/onboarding/done` | 온보딩 완료 후 홈 진입 |
| 홈 | `/` | 잔액 요약, 소멸 안내, 주요 기능 진입 |
| 오늘 뭐 먹지 | `/result` | 카카오 지도, 카테고리·조건 필터, 추천 목록 |
| 편의점에서 균형 있게 | `/cvs` | 1식 한도 내 추천 조합, 가까운 편의점 |
| 가맹점 상세 | `/store/[id]` | 메뉴·영업시간·거리, 즐겨찾기, 길찾기, 제보 |
| 한끼 도우미 | `/chat` | 음식·잔액·복지·동네 변경 대화 흐름 |
| 잔액 입력 | `/balance` | 잔액 수정, 권장 사용액·소멸 예상액 |
| 받을 수 있는 혜택 | `/welfare` | 사용자 조건에 맞는 복지 제도 목록 |
| 내정보 | `/me` | 조건·동네·즐겨찾기·알림·지도 연결 상태 |

하단 탭은 홈, 오늘 뭐 먹지, 한끼 도우미, 내정보의 네 영역을 제공한다. 상세 설정은 바텀시트를 활용해 기준 HTML의 사용 흐름을 유지한다.

## 5. 주요 기능 명세

### 5.1 온보딩과 상태 저장

- 첫 방문자는 동네와 잔액을 순서대로 설정하고 잔액 입력은 건너뛸 수 있다.
- 완료 여부는 브라우저 저장소와 쿠키에 함께 기록한다.
- 서버 프록시는 쿠키를 확인해 미완료 사용자를 온보딩으로 보낸다.
- 주요 설정은 현재 기기의 `localStorage`에 저장한다.

### 5.2 잔액 관리

- 현재 잔액, 남은 사용 가능일, 하루 권장 사용액을 표시한다.
- 선택한 규칙에 따라 월말 또는 연말 예상 소멸액을 계산한다.
- 공식 규정이 확인되지 않은 지역은 보수적 기준과 담당 기관 확인 안내를 표시한다.

### 5.3 가맹점 탐색과 추천

추천은 외부 AI가 아니라 설명 가능한 규칙 기반 로직으로 동작한다.

1. 선택 동네의 가맹점을 불러온다.
2. 업종, 현재 영업 여부, 혼밥 친화, 포장 가능, 1만 원 이하를 필터링한다.
3. 거리, 메뉴 균형, 최근 식사 기록, 결제 불가 제보 상태를 반영해 정렬한다.
4. 지도 마커와 목록을 같은 상세 화면으로 연결한다.

가맹점은 춘천시 공공데이터를 전처리한 정적 JSON을 사용한다. 주소 좌표 변환은 배포 중이 아니라 로컬 데이터 갱신 작업에서 카카오 로컬 REST API로 수행한다.

### 5.4 편의점 균형 조합

- 편의점 이용 자체를 실패로 취급하지 않는다.
- 밥·단백질·우유 또는 과일을 함께 고르는 조합을 제공한다.
- 조합 합계와 1식 한도 충족 여부를 표시하고 영업 중인 가까운 편의점으로 연결한다.

### 5.5 가맹점 상세와 지도

- 가게명, 거리, 영업 여부, 메뉴·가격, 혼밥·포장 여부를 표시한다.
- 카카오맵 보기와 길찾기는 카카오맵 외부 URL로 연결한다.
- 즐겨찾기는 브라우저에 저장해 홈·내정보에 반영한다.
- 결제 불가 제보가 들어온 가게는 확인 전까지 추천 순위를 낮춘다.

### 5.6 한끼 도우미와 복지 정보

- 입력을 음식, 편의점, 잔액, 복지, 동네 변경 등으로 분류한다.
- 추천 대화에서는 혼밥 여부와 식사 방식을 확인한 뒤 가게·메뉴를 제시한다.
- MVP는 규칙 기반이며 알 수 없는 질문에는 지원 가능한 항목을 안내한다.
- 가족 유형과 학교급을 기준으로 복지 제도를 매칭하지만 자격 확정이나 신청 대행은 하지 않는다.

## 6. 데이터와 개인정보

| 데이터 | 저장 위치 | 내용 |
|---|---|---|
| 가맹점 | `data/stores.json` | 좌표, 업종, 영업시간, 메뉴, 이용 배지 |
| 복지 | `data/welfare.json` | 대상 조건, 상태, 문의처, 출처 |
| 사용자 설정 | 브라우저 | 동네, 잔액, 즐겨찾기, 식사 기록, 제보, 조건, 알림 설정 |

- MVP에는 회원가입과 서버 데이터베이스가 없다.
- 가족 유형과 학교급은 혜택 매칭에 필요한 최소 범위로만 받는다.
- 카드번호, 결제내역, 정확한 주소는 수집하지 않는다.
- 기기·브라우저를 바꾸거나 저장 데이터를 지우면 설정이 복구되지 않는다.

## 7. 기술 구성

- Next.js 16 App Router, React 19, TypeScript
- 기준 HTML의 디자인 토큰을 반영한 전역 CSS
- 카카오맵 JavaScript SDK
- 카카오 로컬 REST API 기반 로컬 지오코딩 스크립트
- React 훅 + `localStorage`, 온보딩 리다이렉트용 쿠키
- 빌드에 포함되는 정적 JSON
- Vercel 배포

### 카카오 API 키 구분

| 환경변수 | 용도 | 노출 | Vercel |
|---|---|---|---|
| `NEXT_PUBLIC_KAKAO_MAP_KEY` | 브라우저 지도 | 브라우저 번들에 공개 | Production·Preview 등록 |
| `KAKAO_REST_API_KEY` | 로컬 주소 좌표 변환 | 로컬 스크립트만 사용 | 등록하지 않음 |

JavaScript 키는 카카오 개발자 콘솔의 **허용 도메인 제한**으로 보호한다. 로컬 주소와 실제 Vercel 도메인을 JavaScript SDK 도메인에 등록한다.

## 8. Vercel 배포 요구사항

1. Git 저장소를 Vercel 프로젝트에 연결한다.
2. Framework Preset은 Next.js, 빌드 명령은 `npm run build`를 사용한다.
3. Production과 Preview 환경에 `NEXT_PUBLIC_KAKAO_MAP_KEY`를 등록한다.
4. 카카오 개발자 콘솔에 `http://localhost:3000`, 실제 Production 도메인, 필요한 Preview 도메인을 등록한다.
5. 공개 환경변수는 빌드 시 포함되므로 값을 변경한 뒤 재배포한다.
6. 배포 후 온보딩, 지도, 마커 선택, 상세, 외부 카카오맵 링크를 모바일에서 점검한다.

## 9. 수용 기준

- 기준 HTML의 내용과 체크섬이 개발 전후 동일하다.
- `npm run lint`가 오류 없이 끝나고 `npm run build`가 성공한다.
- 카카오 키가 없어도 앱은 깨지지 않고 설정 안내를 표시한다.
- 키가 있으면 지도와 마커가 표시된다.
- 온보딩 완료, 동네 변경, 잔액 수정 결과가 관련 화면에 일관되게 반영된다.
- 필터와 결제 불가 제보 상태가 추천 결과에 반영된다.
- 모바일 너비에서 주요 버튼과 하단 탭을 사용할 수 있다.

## 10. 배포 전 확인과 향후 단계

### 배포 전 필수

- 생성형 AI는 정확성, 비용, 개인정보와 아동 안전 기준을 정의한 뒤 별도 단계로 검토
